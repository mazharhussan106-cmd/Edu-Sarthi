term: Data intervals
cue: Which idea explains what time period a DAG run is responsible for?
category: Core concept
frequency: Very high
importance: 5
origin: A daily run processes a whole day of data that has already finished, so each run is tied to an interval rather than to the moment it starts.
pro_tip: Remember that a run starts after its interval ends.
memory_story: A data interval is a page of a diary that can only be read after the day is over.
visual: A timeline with an interval shaded and the run starting at its end.
emotion: The aha moment when the run date finally makes sense.
definition: A data interval is the time period a DAG run covers, with a start and an end, and the run is triggered at the end of that period.
explanation: For a daily schedule, the run with logical date 1 October covers 1 October 00:00 to 2 October 00:00 and actually starts on 2 October. The values data_interval_start and data_interval_end give the period. The older name execution date confused many people. Using the interval in queries makes each run process exactly its own period. This describes interval-based timetables (the Airflow 2 default). In Airflow 3 cron schedules run at the trigger time unless you use CronDataIntervalTimetable.
simple_explain: Each run owns a period, and it starts when that period has finished.
analogy: A data interval is a page of a diary that can be read only after the day is over.
formula_rule: Run starts at the interval end and processes the interval.
example_1: The run for 1 October starting early on 2 October.
example_2: A query using data_interval_start and data_interval_end.
example_3: A weekly DAG covering seven days per run.
related: schedules, templating, catchup and backfill, idempotency

where_used: Incremental loads | Reports | Backfills

category: Core concept
