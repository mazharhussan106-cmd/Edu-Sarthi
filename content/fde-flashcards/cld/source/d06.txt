topic: 08 Choosing and Mapping
level: Intermediate
term: Choosing between functions, containers and virtual machines
cue: Which questions decide whether to run code on a function, a container service or a virtual machine?
category: Reference
frequency: High
importance: 4
origin: Cloud offers several ways to run code, so teams need a simple method to pick the right one for each job.
pro_tip: Start with the most managed option that fits, and move down only when you need more control.
memory_story: It is choosing between a taxi, a rented car and owning a car.
visual: A ladder from functions to containers to virtual machines, with control growing downward.
emotion: The ease of a clear rule of thumb.
definition: Functions suit short event-driven tasks, container services suit long-running packaged apps, and virtual machines suit workloads that need full control of the operating system.
explanation: Functions have time limits and stateless design but need no servers. Containers give portability and steady services with moderate effort. Virtual machines give maximum control but need patching and sizing. Consider run time, traffic pattern, state, skills and cost. Spiky, short jobs favour functions, steady services favour containers, and legacy or special software favours virtual machines.
simple_explain: Use the most managed option that fits the job, and move toward more control only when needed.
analogy: It is choosing between a taxi, a rented car and owning a car.
formula_rule: More control means more work. Pick the least you need.
example_1: A nightly cleanup as a function.
example_2: A web API as a container service.
example_3: Licensed legacy software on a virtual machine.
related: serverless functions, container services, virtual machines, cost
word_family: function, container, virtual machine, control, managed
where_used: Architecture decisions | Customer designs | Migrations
mini_conversation: A: Should we use a server for this small task? | B: A function is simpler if it finishes quickly.
misconception: ✗ Virtual machines are always the safest default → ✓ A more managed option often costs less effort and fits better
contrast: Function vs container: a function is short and event-driven, a container service runs steadily.
avoid: Do not use functions for jobs that run longer than their limit.
memory_trick: Least control that works wins.
real_project: Choosing containers for a steady API and functions for its nightly cleanup jobs.
