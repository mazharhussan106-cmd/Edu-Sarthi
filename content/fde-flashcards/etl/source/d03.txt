cue: Which property means running a job twice gives the same result as running it once?
kind: Reliability principle
frequency: Very high
importance: 5
origin: Jobs fail halfway and get retried, so safe pipelines are designed so that repeating a run never duplicates or corrupts data.
pro_tip: Replace by key or partition instead of appending blindly.
memory_story: An idempotent job is a light switch, where pressing on twice still leaves the light on.
visual: Two identical runs leading to the same final table.
emotion: The confidence to rerun anything at three in the morning.
meaning: An idempotent job produces the same final state however many times it runs with the same input, usually by upserting or replacing a partition.
code: BEGIN;¶DELETE FROM fct_sales WHERE sale_date = DATE '2026-10-01';¶INSERT INTO fct_sales SELECT * FROM stg_sales WHERE sale_date = DATE '2026-10-01';¶COMMIT;
output: Rerunning the block always leaves exactly one copy of that day's sales.
explanation: Appending rows on every run creates duplicates after a retry. Delete and insert for one day inside a transaction, or write to a temporary table and swap, makes the run repeatable. Upserts by key give the same effect. Runs should depend on the logical date, not the current time. Side effects such as emails need their own guard.
simple_explain: Make each run replace its own slice of data, so a retry changes nothing.
analogy: An idempotent job is a light switch, where pressing on twice still leaves the light on.
