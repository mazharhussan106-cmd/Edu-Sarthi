term: Why evaluate
cue: Why must AI applications be tested with measurements and not by feel?
category: Core concept
frequency: Very high
importance: 5
origin: AI outputs vary and failures are subtle, so teams that only try a few examples ship problems that appear later with real users.
pro_tip: Define what good means before building, then measure it from the first prototype.
memory_story: Evaluation is the scoreboard that tells you whether a change really helped.
visual: A scoreboard comparing two versions on the same questions.
emotion: The confidence of decisions backed by numbers.
definition: Evaluation is the systematic measurement of how well an AI system performs on defined tasks, using test cases, metrics and reviews, so changes can be compared and risks found early.
explanation: Without evaluation, changes to prompts, models or retrieval are guesses. A good evaluation covers typical cases, hard cases and failures. It supports choosing models, catching regressions, setting release gates and reporting quality to customers. It does not need to be big at first, since fifty good examples are better than none.
simple_explain: Measure quality on a fixed set of cases so you can compare changes and find problems early.
analogy: Evaluation is the scoreboard that tells you whether a change helped.
formula_rule: Cases + metrics + comparison = evidence.

example_2: Blocking a release that lowers accuracy.
example_3: Choosing a cheaper model after testing.
