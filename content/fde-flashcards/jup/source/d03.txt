topic: 03 Good practice
level: Intermediate
term: Reproducibility
cue: What makes someone else get the same results from your notebook?
category: Good practice
frequency: Very high
importance: 5
origin: A result that nobody else can recreate is hard to trust, review or reuse.
pro_tip: Record the data source, package versions and random seeds inside the notebook itself.
memory_story: A reproducible notebook is a recipe with exact amounts, not a vague description of a meal.
visual: A checklist with data, packages, seed and order all ticked.
emotion: The trust of results that others can repeat.
definition: A reproducible notebook gives the same results when another person runs it from top to bottom on their own machine, because its inputs, packages, randomness and order are all stated.
explanation: Four things usually break reproducibility: hidden state, unpinned package versions, missing or changing data, and unseeded randomness. Fix them by running clean, listing versions in a requirements file, noting where data comes from, and setting seeds. Use relative paths so the notebook does not depend on your own folders.
simple_explain: Someone else should be able to run your notebook and get the same answer.
analogy: A reproducible notebook is a recipe with exact amounts, not a vague description of a meal.
formula_rule: Same data, same packages, same seed, same order.
example_1: A requirements file stored beside the notebook.
example_2: A fixed random seed in a sampling step.
example_3: A relative path to a data folder inside the project.
related: running order, restart and run all, installing packages, version control
word_family: reproducible, seed, pinned, relative path, environment
where_used: Research | Client reports | Audits
mini_conversation: A: My numbers differ from yours. | B: Let us compare package versions and the random seed.
misconception: ✗ If it runs on my laptop it is reproducible → ✓ It must also run cleanly on another machine
contrast: Reproducible vs repeatable: others can recreate it versus you can rerun it yourself.
avoid: Do not hard-code paths that exist only on your own computer.
memory_trick: Pin the versions, fix the seed, share the data path.
real_project: Pinned package versions let an audit team recreate a client's numbers months later.
real_interview: An interviewer may ask: How do you make a notebook reproducible?
real_daily: It is like a recipe with exact measurements.
mcq_question: Which item helps make random steps repeatable?

mcq_answer: D
mcq_why: A seed makes random choices follow the same sequence.
fill_blank: A path that starts from the project folder is called a ____ path → relative
apply: Two analysts get different sampled rows. What do you add? → A fixed random seed

Load it from the environment or from a local file that is ignored by version control. If a secret leaks, treat it as compromised and rotate it, since deleting the cell does not remove the old copies. Print only that a key exists, never its value.
