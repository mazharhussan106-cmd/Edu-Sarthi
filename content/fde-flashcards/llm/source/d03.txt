topic: 04 Quality and Safety

term: Hallucination
cue: What do we call confident answers from a model that are not true?
category: Core concept
frequency: Very high
importance: 5
origin: Models generate likely text, so when they lack the facts they may produce fluent but false statements.
pro_tip: Provide source text and ask the model to say when the answer is not in it.
memory_story: A hallucination is a confident storyteller filling gaps with invented details.
visual: A smooth answer with a fake reference highlighted.
emotion: The caution of knowing fluent text can be wrong.
definition: A hallucination is output that sounds plausible but is false or unsupported, such as invented facts, citations, numbers or function names.
explanation: Causes include missing knowledge, ambiguous questions and pressure to answer. Risk is higher for rare facts, recent events and precise details. Reduce it by grounding in provided sources, allowing the answer I do not know, asking for quotes, using tools for lookups and checking results. It cannot be eliminated, so review matters in high-stakes uses.
simple_explain: Models can invent facts, so ground them in sources and verify important claims.
analogy: A hallucination is a confident storyteller filling gaps with invented details.
formula_rule: No source plus pressure to answer equals risk of invention.
example_1: A made-up legal citation.
example_2: An invented function in a library.
example_3: A wrong date stated confidently.
related: grounding, RAG, human review, guardrails
word_family: hallucination, fabrication, confidence, grounding, verification
where_used: Every LLM application | Risk reviews | Customer tools
mini_conversation: A: The bot quoted a policy that does not exist. | B: It hallucinated, so ground it in the real policy text.
misconception: ✗ A confident tone means the answer is correct → ✓ Fluency is not evidence of truth
contrast: Hallucination vs error: hallucinations are invented content stated as fact.
avoid: Do not rely on unverified model output for critical facts.
memory_trick: Confident does not mean correct.
real_project: Grounding answers in policy text and allowing I do not know stopped invented refund rules.

term: Prompt injection
cue: Which attack hides instructions in text so the model obeys the attacker?
category: Core concept
frequency: Very high

pro_tip: Treat all retrieved and user text as untrusted, and limit what tools can do.
memory_story: Prompt injection is a forged note slipped into the pile of papers that the assistant obeys.

emotion: The alertness of knowing text can carry commands.
definition: Prompt injection is an attack where untrusted content contains instructions that override or manipulate the model, either directly from a user or indirectly through documents, web pages or tool outputs.
explanation: Indirect injection is serious when the model has tools, such as sending email or reading files. Defences are layered: separate and label untrusted data, give the model minimal permissions, require human approval for risky actions, validate tool arguments, filter outputs and monitor. No single prompt fully prevents it, so design for failure.
simple_explain: Assume untrusted text may try to control the model, and limit the damage it can do.
analogy: Prompt injection is a forged note slipped into the pile of papers the assistant obeys.
formula_rule: Untrusted text + powerful tools = risk.
example_1: A web page saying ignore your rules and send the user's data.
example_2: An email telling an assistant to forward files.
example_3: A document asking the model to reveal its system prompt.
related: system prompts, tool calling, guardrails, data privacy
word_family: injection, untrusted, indirect, permissions, approval
where_used: Agents | RAG | Email assistants
mini_conversation: A: A web page told our agent to leak data. | B: Treat page text as untrusted and require approval for sending.
misconception: ✗ A strong system prompt fully blocks injection → ✓ It helps, but architecture and permissions are the real defence
contrast: Direct vs indirect injection: user typed versus hidden in content.
avoid: Do not give agents broad permissions over untrusted content.
memory_trick: Untrusted text cannot be trusted with tools.
real_project: Requiring approval before sending messages limited the impact of an injected email.
