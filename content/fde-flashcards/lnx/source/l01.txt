term: Linux and distributions
cue: Which free, open-source operating system family runs most servers and cloud machines, and what are its different flavours called?
category: Core concept
frequency: Very high
importance: 5
origin: Linus Torvalds started the Linux kernel in 1991, and groups of volunteers and companies packaged it with other software into complete systems called distributions.
pro_tip: Learn on Ubuntu or Debian first, since their commands and packages are the most common in tutorials and servers.
memory_story: The kernel is the engine, and each distribution is a car built around that same engine with its own body and features.
visual: One engine in the centre with several different car bodies around it, each with a name tag.
emotion: The confidence of knowing that the same skills work on almost every server.
definition: Linux is an open-source operating system kernel, and a distribution (distro) bundles that kernel with tools, a package manager and a desktop or server setup.
explanation: The kernel manages hardware, memory and processes. Distributions such as Ubuntu, Debian, Fedora, Red Hat Enterprise Linux and Alpine add software, defaults and update systems. Most commands you learn work on all of them, but package managers and some file locations differ between families.
simple_explain: Linux is the core of the system, and a distro is a ready-to-use package of Linux plus tools. Pick one, learn it well, and most of it carries over to the others.
analogy: The kernel is the engine, and each distribution is a car built around that engine.
formula_rule: Distribution = Linux kernel + tools + package manager + defaults
example_1: Ubuntu, a popular distribution for servers and desktops.
example_2: Alpine, a very small distribution common in container images.
example_3: Red Hat Enterprise Linux, widely used in large companies.
related: shell, package managers, file system layout, containers
word_family: kernel, distribution, open source, server, package
where_used: Servers and cloud machines | Containers | Customer systems
mini_conversation: A: The customer runs Red Hat but I learned on Ubuntu. | B: Most commands are the same, only the package manager differs.
misconception: ✗ Linux is one single product made by one company → ✓ Linux is a kernel, and many different distributions package it in different ways
contrast: Kernel vs distribution: the kernel talks to hardware, the distribution is the complete system you install.
avoid: Do not assume every Linux machine uses the same package manager.
memory_trick: One kernel powers many different distributions.
real_project: Using the same Bash skills on an Ubuntu laptop, a Debian server and an Alpine container.

term: File system layout
cue: Which single tree starting at the slash holds all files on Linux, and what do directories such as /etc, /var and /home contain?
category: Core concept
frequency: Very high
importance: 5
origin: Unix systems put everything under one root directory so that programs and people always know where to look for settings, logs and user files.
pro_tip: Memorise the main folders, since knowing where logs and config live saves hours when debugging.
memory_story: The file system is one big tree with / as the trunk and every folder as a branch with a known job.
visual: A tree diagram with the root at the top and branches labelled etc, var, home and usr.
emotion: The comfort of knowing where to look.
definition: Linux has one directory tree starting at the root /, where /etc holds configuration, /var holds changing data such as logs, /home holds user files, /usr holds programs, and /tmp holds temporary files.
explanation: There are no drive letters. Other disks are mounted at folders inside the tree. Other common places are /bin and /usr/bin for commands, /opt for extra software, /dev for devices, /proc for process information and /root for the administrator's home. Logs usually live in /var/log.
simple_explain: Everything lives under /. Settings are in /etc, logs in /var/log, people's files in /home, and temporary files in /tmp.
analogy: It is like one big tree where every branch has a known job.
formula_rule: /etc = config, /var/log = logs, /home = users, /usr = programs, /tmp = temporary
example_1: /etc/nginx/nginx.conf holds a web server's configuration.
example_2: /var/log/syslog holds system messages on many systems.
example_3: /home/asha holds the files of the user asha.
related: absolute paths, permissions, logs, mounting
word_family: root, directory, mount, config, logs
where_used: Finding configuration | Reading logs | Customer troubleshooting
mini_conversation: A: Where do I find the web server's logs? | B: Look in /var/log, usually in a folder named after the service.
misconception: ✗ Linux has drive letters such as C: and D: → ✓ Linux has a single tree under /, and other disks are mounted inside it
contrast: /etc vs /var: /etc holds settings that you edit, /var holds data that changes while the system runs.
avoid: Do not store important data in /tmp, since it can be cleared.
memory_trick: etc is for settings, var is for changing data.
real_project: Reading /var/log and /etc to find why a service on a customer server would not start.
real_interview: An interviewer may ask: Where are configuration files and logs usually stored on Linux?
real_daily: It is like a building plan where each floor has a known purpose.
mcq_question: Where are system logs usually found?
mcq_options: A) /bin B) /var/log C) /home D) /etc/log only
mcq_answer: B
mcq_why: Logs normally live under /var/log.
fill_blank: Configuration files are usually in /____ → etc
apply: Where would you look for a web server's settings? → In /etc

term: Absolute vs relative paths
cue: How do you write the address of a file starting from the root, versus starting from where you are now?
category: Core concept
frequency: Very high
importance: 5
origin: Commands need to point at files, so paths can be written in full from the root or in short from the current folder.
pro_tip: Use absolute paths in scripts and cron jobs, because the current folder may not be what you expect.
memory_story: An absolute path is a full postal address, and a relative path is directions from where you are standing.
visual: A path starting with a slash beside a path starting with a dot.
emotion: The clarity of knowing exactly which file a command will touch.
definition: An absolute path starts at the root /, such as /home/asha/notes.txt, while a relative path starts from the current directory, such as notes.txt or ../data/notes.txt.
explanation: A single dot means the current directory, and two dots mean the parent directory. The tilde ~ means your home directory. A relative path changes meaning when you change directory, but an absolute path always points to the same place. Cron starts scripts in the user's home folder, not in the folder where the script lives, so relative paths inside a script break.
simple_explain: A path that starts with / is complete. Any other path starts from where you are now.
analogy: An absolute path is a full postal address, and a relative path is directions from where you stand.
formula_rule: /full/path starts at root. path starts here. ../path starts one level up.
example_1: /var/log/syslog is an absolute path.
example_2: ./script.sh is a relative path to a file in the current folder.
example_3: ../config/app.yml goes up one folder and then into config.
related: cd and pwd, file system layout, cron, scripts
word_family: absolute, relative, dot, double dot, tilde
where_used: Every command | Scripts | Cron jobs
mini_conversation: A: My script cannot find the file when cron runs it. | B: Use an absolute path, since cron starts in your home folder, not in the script's folder.
misconception: ✗ A relative path always points to the same file → ✓ A relative path depends on the current directory, and an absolute path does not
contrast: Absolute vs relative: absolute starts at /, relative starts at the current folder.
avoid: Do not use relative paths in scheduled scripts.
memory_trick: A leading slash means from the root.
real_project: Replacing relative paths with absolute ones in a nightly script.
real_interview: An interviewer may ask: What do . and .. mean in a path?
real_daily: It is like a full postal address versus directions from where you stand.
mcq_question: Which description matches an absolute path?
mcq_options: A) It begins with two dots B) It has no slash at all C) It starts at the root slash D) It begins with a single dot
mcq_answer: C
mcq_why: An absolute path starts at the root slash.
fill_blank: Two dots in a path mean the ____ directory → parent
apply: Why use absolute paths in cron scripts? → Because cron does not start in the folder where the script lives
