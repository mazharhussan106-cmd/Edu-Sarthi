term: tmux (terminal multiplexer)
cue: Which tool keeps terminal sessions alive on a server and lets you split the screen and reattach after a disconnect?
kind: Command
frequency: High
importance: 4
origin: Remote connections drop, and long-running work should survive, so terminal multiplexers keep sessions running on the server independent of your connection.
pro_tip: Start a named session with tmux new -s work, so you can find it again.
memory_story: tmux is a desk that stays set up on the server, whether or not you are sitting at it.
visual: A terminal split in panes, with a detach and reattach arrow.
emotion: The freedom of dropped connections no longer mattering.
meaning: tmux runs persistent terminal sessions that you can detach from, reattach to, and split into windows and panes.
code: tmux new -s work¶tmux ls¶tmux attach -t work¶tmux kill-session -t work
output: A new session named work, a list of sessions, a reattached session after a disconnect, and the session removed.
explanation: Inside tmux, most commands start with the prefix Ctrl and B. After the prefix, d detaches, c creates a new window, % splits the window into left and right panes, and double quote into top and bottom panes. A session continues to run when you detach or lose your connection. screen is an older, similar tool.
simple_explain: Start tmux, work, and detach with the prefix and d. Later reattach with tmux attach, and everything is still running.
analogy: It is like a desk on the server that stays set up whether or not you sit at it.
syntax: tmux new -s name  |  tmux attach -t name
anatomy: new -s = new named session | attach -t = reattach | prefix then d = detach | ls = list
example_1: tmux new -s deploy
example_2: tmux attach -t deploy
example_3: tmux ls
variation: tmux new -d -s job 'long_command'   // start detached¶prefix then [   // scroll mode
used_with: ssh, long jobs, nohup
related: background jobs, ssh, screen
alternatives: screen
where_used: Remote servers | Long jobs | Pairing sessions
mini_conversation: A: My SSH dropped and killed my job. | B: Run long jobs inside tmux, then reattach later.
misconception: ✗ Closing the terminal window always ends a tmux session → ✓ A tmux session keeps running on the server when you detach or lose the connection
confused_with: tmux vs nohup: tmux keeps an interactive session, nohup only protects one command.
avoid: Do not leave many forgotten sessions running.
wrong_code: tmux attach work
right_code: tmux attach -t work
memory_trick: Always detach and do not kill.
real_project: Running a long data migration in tmux on a customer server.
real_interview: An interviewer may ask: How do you keep a session alive after SSH disconnects?
real_daily: It is like a desk that stays set up on the server.
mcq_question: What does detaching from tmux do?
mcq_options: A) Leaves the session running B) Ends the session C) Reboots the machine D) Deletes files
mcq_answer: A
mcq_why: A detached session keeps running on the server.
fill_blank: The default tmux prefix is Ctrl and ____ → B
hindi_to_task: Start a tmux session named work.
task_answer: tmux new -s work
own_task: Start a session, run a command, detach and reattach.

practice_answer: tmux ls

term: lsof and strace
cue: Which tools show which files and ports a process has open, and which system calls it makes?
kind: Command
frequency: Medium
importance: 4
origin: When a program misbehaves without a clear error, you can watch what it asks the kernel to do, so these tools expose open files and system calls.
pro_tip: Use lsof -i :port to find who holds a port, and strace -f -p pid to see what a running program is doing.
memory_story: lsof lists what a process is holding in its hands, and strace listens to every request it makes to the kernel.
visual: A process surrounded by the files and sockets it holds.
emotion: The detective's thrill of finding a hidden cause.
meaning: lsof lists open files and sockets, and strace traces the system calls of a program.
code: sudo lsof -i :8080¶lsof -p 1234¶strace -f -o trace.txt ./program¶sudo strace -p 1234
output: The process using port 8080, the files and sockets of process 1234, a trace of every system call written to a file, and a live trace of a running process.
explanation: On Linux, almost everything is a file, including sockets, so lsof shows files, network connections and even deleted files still held open. strace shows calls such as open, read and connect, with their results, which reveals missing files, permission errors and slow calls. strace slows the program down, so use it with care on busy systems.
simple_explain: Use lsof to see what a process has open or who uses a port. Use strace to see which system calls a program makes and where it fails.
analogy: lsof lists what a process holds in its hands, and strace listens to each request it makes.
syntax: lsof [-i :port] [-p pid]  |  strace [-f] [-p pid] command
anatomy: lsof -i = network files | -p = by process | strace -f = follow child processes | -o = write to file
example_1: sudo lsof +D /var/log
example_2: strace -e trace=openat ./app
example_3: sudo lsof | grep deleted
variation: strace -c ./app   // summary of time spent per call¶lsof -u asha   // files opened by a user
used_with: ps, ss, grep
related: ss, ps and top, df
alternatives: ltrace for library calls, or a debugger
where_used: Port conflicts | Mystery failures | Disk space held by deleted files
mini_conversation: A: The app exits with no error message. | B: Run it under strace and look for failed open calls near the end.
misconception: ✗ strace has no effect on the program speed → ✓ strace can slow a program a lot, so use it carefully on production systems
confused_with: lsof vs strace: lsof shows what is open now, strace shows calls over time.
avoid: Do not attach strace to a busy production process casually.
wrong_code: lsof port 8080
right_code: sudo lsof -i :8080
memory_trick: lsof shows holdings, strace shows requests.
real_project: Finding that a missing config file path was the cause of a silent crash.
real_interview: An interviewer may ask: How do you find which process uses a port?
real_daily: It is like seeing what someone holds in their hands.
mcq_question: Which tool traces system calls?
mcq_options: A) tar B) strace C) df D) lsof
mcq_answer: B
mcq_why: strace follows the system calls a process makes.
fill_blank: The tool that traces the system calls of a program is called ____ → strace
hindi_to_task: Show which process uses port 3000.
task_answer: sudo lsof -i :3000
own_task: Use strace on a simple command and find the files it opens.
practice_question: Why can deleted files still use disk space?
practice_answer: Because a process may still hold them open.

term: tar and gzip
cue: Which commands bundle many files into one archive and compress it, and unpack it again?
kind: Command
frequency: Very high
importance: 5
origin: Moving many files is easier as one package, so tar joins them into an archive and compression tools such as gzip make it smaller.
pro_tip: List an archive with tar -tzf before extracting, to see where the files will land.
memory_story: tar packs a box with everything inside, and gzip squeezes the box smaller.
visual: A folder going into one file ending in tar dot gz.
emotion: The ease of moving a whole folder as one file.
meaning: tar creates and extracts archives, and with -z it uses gzip compression.
code: tar -czf backup.tar.gz project/¶tar -tzf backup.tar.gz¶tar -xzf backup.tar.gz -C /tmp/restore¶gzip file.log¶gunzip file.log.gz
output: A compressed archive of the folder, a list of its contents, the contents extracted into a chosen folder, a single file compressed, and then decompressed.
explanation: The flag c creates, x extracts, t lists, f names the file, z uses gzip, and v shows progress. The -C option picks the target folder for extraction. tar keeps permissions and folder structure. gzip works on single files, and tar combines files so that one compressed file holds a whole folder. Other formats include .zip with the zip and unzip commands.
simple_explain: Use tar -czf to pack and compress, tar -tzf to look inside, and tar -xzf to unpack. Add -C to choose where it goes.
analogy: tar packs a box with everything inside, and gzip squeezes the box smaller.
syntax: tar -czf archive.tar.gz folder  |  tar -xzf archive.tar.gz
anatomy: c = create | x = extract | t = list | z = gzip | f = file name | -C = target folder
example_1: tar -czf site.tar.gz /var/www/site
example_2: tar -xzf site.tar.gz -C /var/www
example_3: tar -tzf site.tar.gz | head
variation: tar -cjf a.tar.bz2 folder   // bzip2 compression¶unzip file.zip   // for zip archives
used_with: scp, cron backups, rsync
related: scp and rsync, cron, find
alternatives: zip and unzip
where_used: Backups | Moving folders | Releases
mini_conversation: A: I need to send the whole folder to the customer. | B: Pack it with tar -czf and send the single archive.
misconception: ✗ gzip can compress a whole folder by itself → ✓ gzip compresses single files, and tar bundles a folder into one file first
confused_with: tar vs gzip: tar bundles files, gzip compresses a file.
avoid: Do not extract an archive from an unknown source without listing it first.
wrong_code: tar -xzf backup.tar.gz /tmp/restore
right_code: tar -xzf backup.tar.gz -C /tmp/restore
memory_trick: Create, extract and list with c, x and t.
real_project: Archiving a release folder before copying it to a customer server.
real_interview: An interviewer may ask: What does tar -xzf do?
real_daily: It is like packing a box and squeezing it smaller.
mcq_question: Which flag of tar extracts an archive?
mcq_options: A) z B) t C) x D) c
mcq_answer: C
mcq_why: x stands for extract.
fill_blank: In tar -czf, the letter z means ____ compression → gzip

task_answer: tar -czf logs.tar.gz logs
