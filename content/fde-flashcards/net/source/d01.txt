@NET-001
topic: 01 Models
level: Beginner
term: OSI and TCP/IP layers
cue: Which layered models describe how data travels from an application down to the wire and back?
category: Core concept
frequency: Very high
importance: 5
origin: Networks involve many different jobs, so engineers split them into layers where each layer does one task and relies on the one below.
pro_tip: Use the layers to place a problem, such as cable at layer one or a web error at layer seven.
memory_story: The layers are like a postal chain, with the letter, the envelope, the sorting office and the truck each doing one job.
visual: A stack of boxes from application at the top down to physical at the bottom.
emotion: The clarity of knowing where in the stack a problem lives.
definition: The OSI model has seven layers and the TCP/IP model has four, and both describe how application data is wrapped step by step for sending and unwrapped on arrival.
explanation: OSI layers from the bottom are physical, data link, network, transport, session, presentation and application. TCP/IP groups them into link, internet, transport and application. Ethernet and Wi-Fi sit low, IP at the network layer, TCP and UDP at the transport layer, and HTTP and DNS at the application layer. Each layer adds its own header, which is called encapsulation.
simple_explain: Data moves down the layers when sent, picking up headers, and up the layers when received, losing them.
analogy: The layers are a postal chain where the letter, the envelope, the sorting office and the truck each do one job.
formula_rule: Application data + header at each layer = encapsulation.
example_1: HTTP at the application layer carrying a web page request.
example_2: TCP at the transport layer splitting the data into numbered segments.
example_3: IP at the network layer adding source and destination addresses.
related: packets and frames, TCP vs UDP, routers and switches, troubleshooting method
word_family: layer, encapsulation, header, protocol, stack
where_used: Troubleshooting | Interviews | Network design
mini_conversation: A: Is the cable the problem or the website? | B: Check the lower layers first, then work upward.
misconception: ✗ The OSI model is how the internet is actually built → ✓ OSI is a teaching reference, and the internet follows the simpler TCP/IP model
contrast: OSI vs TCP/IP: OSI has seven layers for teaching, TCP/IP has four and matches real protocols.
avoid: Do not memorise layers without linking each to a real protocol.
memory_trick: Please do not throw sausage pizza away.
real_project: Using the layers to prove that a customer outage was a DNS problem, not a cable fault.
real_interview: An interviewer may ask: At which layer does a router work?
real_daily: It is like a postal chain with one job per step.
mcq_question: At which OSI layer does IP work?
mcq_options: A) Session layer B) Application layer C) Physical layer D) Network layer
mcq_answer: D
mcq_why: IP handles addressing and routing at the network layer.
fill_blank: Adding a header at each layer is called ____ → encapsulation
apply: A web page fails but pings work. Which layers are likely fine? → The lower layers
explain_task: Explain the layered model in three lines.
own_task: Match five common protocols to their layers in the stack.

term: Packets and frames
cue: Which units carry data at the network and link layers?
category: Core concept
frequency: High

origin: Sending a big file in one piece would block the line and lose everything on error, so data is cut into small labelled units.
pro_tip: Think of a packet as the letter and a frame as the envelope for one hop.

explanation: A packet keeps its source and destination IP addresses from end to end. A frame has MAC addresses and is rebuilt at every hop. Frames have a size limit called the MTU. Large data is split into many packets and reassembled at the destination. Lost packets may be retransmitted by TCP.
simple_explain: Packets travel end to end, and each hop puts them into a fresh frame.
analogy: A packet is a letter with its address, and a frame is the local delivery bag it rides in for one stretch.
formula_rule: Packet = end-to-end address. Frame = hop-by-hop address.
example_1: A web request split into several packets.
example_2: A router stripping the old frame and building a new one.
example_3: A frame limited to 1500 bytes of payload.
related: OSI layers, MAC and ARP, MTU, routers
word_family: packet, frame, header, payload, MTU
where_used: Packet captures | Troubleshooting | Performance work

A satellite link may have high bandwidth but high latency. Throughput is the speed you actually achieve, which can be below bandwidth. Many small requests suffer from latency, which is why connections are reused.

formula_rule: Transfer time ≈ latency + data size ÷ bandwidth.

simple_explain: The slash number tells how many bits are the network, and the rest are for hosts.
analogy: CIDR is a ruler that slides the line between network and host.

origin: On a local network frames need a hardware address, so devices use ARP to find the one that matches a given IP.
pro_tip: If two devices cannot talk on one subnet, check the ARP table.
memory_story: ARP is shouting who has this IP and waiting for the owner to shout back their hardware name.
visual: A broadcast question and a unicast answer between two devices.
emotion: The satisfaction of watching the table fill as devices talk.
definition: A MAC address is a 48-bit hardware address of a network interface used on the local link, and ARP finds the MAC address that belongs to a given IPv4 address.
explanation: A device wanting to reach a local IP broadcasts an ARP request, and the owner replies with its MAC. The answer is cached in the ARP table for a while. To reach a remote network, a device sends frames to the gateway's MAC. Attackers can forge ARP replies, which is called ARP spoofing. IPv6 uses neighbour discovery instead.
simple_explain: ARP turns an IP address into the MAC address needed on the local link.
analogy: ARP is shouting who has this IP and waiting for the owner to answer with their hardware name.
formula_rule: IP says who, MAC says which card, ARP links them.
example_1: arp -a showing IP and MAC pairs.
example_2: A device sending to the gateway's MAC for outside traffic.
example_3: A duplicate IP showing two MACs for one address.
