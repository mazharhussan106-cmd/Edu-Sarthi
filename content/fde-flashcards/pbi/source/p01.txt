@PBI-001
topic: 01 Basics
level: Beginner
term: Power BI (Desktop, Service, Mobile)
cue: Microsoft's business analytics product comes in three parts. What are they, and what does each part do?
category: Product overview
frequency: Very high
importance: 5
origin: Microsoft built Power BI to let ordinary business users turn raw data into interactive reports without writing a full application.
pro_tip: Build the report in Desktop, publish it to the Service, and use Mobile just to read it on the go.
memory_story: Desktop is the kitchen where you cook, the Service is the restaurant where you serve, and Mobile is the takeaway box.
visual: A laptop, a cloud and a phone are joined by arrows showing a report travelling between them.
emotion: The excitement of seeing messy numbers turn into a clean, clickable dashboard.
definition: Power BI is a set of tools: Desktop to build reports, the Service in the cloud to share them, and Mobile apps to view them.
explanation: Power BI Desktop is a free Windows application for connecting to data, cleaning it, modelling it and designing reports. The Power BI Service (the website) is where you publish, schedule refreshes and share. The mobile apps let people read reports on phones and tablets.
simple_explain: You create the report on your computer with Desktop. You upload it to the Service so others can see it in a browser. People then open it on their phones with the Mobile app.
analogy: It works like writing a document in a word processor, saving it to a shared drive, and reading it on your phone.
formula_rule: Build (Desktop) → Publish and share (Service) → Read anywhere (Mobile)
example_1: An analyst builds a sales report in Power BI Desktop on a laptop.
example_2: The analyst publishes the report to a workspace in the Power BI Service so the sales team can open it in a browser.
example_3: A regional manager checks the same report on a phone while travelling.
related: Power BI Desktop, Power BI Service, semantic model, workspace
word_family: Desktop, Service, Mobile, report, dashboard
where_used: Business reporting | Data analysis jobs | Management dashboards
mini_conversation: A: Where do I create my report? | B: Build it in Power BI Desktop, then publish it to the Service to share it.
misconception: ✗ Power BI is just one program you install on your computer → ✓ Power BI has three parts: Desktop is installed, the Service runs in the cloud, and Mobile is an app
contrast: Desktop vs Service: Desktop is where you build and model, the Service is where you share and manage.
avoid: Do not edit a report only in the Service when it should be maintained in the original Desktop file.
memory_trick: Desktop builds, Service shares, Mobile carries.
real_project: Building a monthly sales report in Desktop and publishing it so managers see fresh numbers each morning.
real_interview: An interviewer may ask: What is the difference between Power BI Desktop and the Power BI Service?
real_daily: It is like cooking at home, serving guests at a restaurant, and packing leftovers to take away.
mcq_question: Which part of Power BI is mainly used to build and model reports on your own computer?
mcq_options: A) Power BI Mobile B) Power BI Service C) Power BI Gateway D) Power BI Desktop
mcq_answer: D
mcq_why: Desktop is the authoring tool, while the Service is for sharing and the Mobile app is for viewing.
fill_blank: You publish a finished report from Desktop to the Power BI ____ so others can open it → Service
apply: Which part would you use to read a report on a phone while travelling? → The Power BI Mobile app
explain_task: Explain the three parts of Power BI to a friend in three lines.
own_task: Write which part of Power BI you would use for each step of making and sharing a report.

term: Semantic model (dataset)
cue: What is the name for the loaded, modelled data that sits behind one or more Power BI reports?
category: Core concept
frequency: Very high
importance: 5
origin: Reports need a shared, well-defined source of data, so Power BI separates the data and logic from the visuals, and this layer was long called a dataset.
pro_tip: Build one good model and let many reports connect to it instead of copying data into every report.
memory_story: The model is the engine room of a ship, and the reports are only the dashboard the captain looks at.
visual: One large block of connected tables with several different reports pointing at it.
emotion: The satisfaction of fixing a number once and seeing every report update.
definition: A semantic model holds the tables, relationships, measures and security that reports use, and it was formerly called a dataset.
explanation: When you import data and build relationships and DAX measures, you create a semantic model. When you publish from Desktop, the model and report go to the Service, where the model can be refreshed and reused by other reports. Microsoft renamed datasets to semantic models.
simple_explain: The semantic model is the data brain behind your report. It stores your tables, links and calculations, and the report just shows the results.
analogy: It is like a restaurant kitchen that cooks the food, while the menu cards are just what the customers see.
formula_rule: Semantic model = tables + relationships + measures + security
example_1: A sales model holds Sales, Product and Date tables linked together.
example_2: Three different reports reuse the same published sales model.
example_3: An administrator refreshes the model once a night so all reports show new data.
related: report, relationships, measures, refresh
word_family: dataset, model, tables, measures, relationships
where_used: Every published report | Shared enterprise models | Self-service analysis
mini_conversation: A: Why do two of our reports show different totals? | B: They use separate copies of the data, so build one shared semantic model.
misconception: ✗ A semantic model and a report are the same thing → ✓ The model holds the data and logic, and a report is only the visuals built on top of it
contrast: Semantic model vs report: the model stores and calculates, the report displays.
avoid: Do not create a new copy of the same data in every report.
memory_trick: Model is the machine, report is the screen.
real_project: Publishing one certified sales semantic model that many team reports connect to.
real_interview: An interviewer may ask: What is a semantic model, and what was it called before?
real_daily: It is like a kitchen that cooks the food while the menu is only what customers see.
mcq_question: What is Power BI's semantic model formerly known as?
mcq_options: A) Gateway B) Workspace C) Dataset D) Dashboard
mcq_answer: C
mcq_why: Microsoft renamed datasets to semantic models.
fill_blank: Reports are built on top of the tables and measures held in a semantic ____ → model
apply: How do you avoid different totals across several reports? → Build one shared semantic model and connect all reports to it
explain_task: Explain the difference between a semantic model and a report in three lines.
own_task: List the tables and measures that would sit in a semantic model for a small shop.

term: Report vs dashboard
cue: Power BI has a multi-page interactive canvas and a one-page canvas of pinned tiles. What are they called?
category: Core concept
frequency: Very high
importance: 5
origin: People need both detailed, explorable pages and one quick overview screen, so Power BI offers reports for depth and dashboards for the big picture.
pro_tip: Pin only the most important visuals to a dashboard so it can be read in a few seconds.
memory_story: A report is a book you read and explore, while a dashboard is the poster on the wall.
visual: A thick book of pages beside a single poster of small tiles.
emotion: The comfort of seeing the key numbers at one glance.
definition: A report is a multi-page, interactive set of visuals built on one model, while a dashboard is a single page of tiles pinned from one or more reports.
explanation: Reports are created in Desktop or the Service and have filters, slicers and many pages. A dashboard exists only in the Service and is made by pinning visuals, so its tiles can come from different reports. Clicking a tile opens the report it came from.
simple_explain: A report is for exploring details across pages. A dashboard is a single overview page made of pinned tiles. Click a tile and you jump to its report.
analogy: A report is a full book and a dashboard is a poster summarising the key points.
formula_rule: Report = many pages, one model. Dashboard = one page, many sources.
example_1: A sales report with pages for regions, products and trends.
example_2: A dashboard with tiles pinned from the sales report and the finance report.
example_3: A manager opens the dashboard and clicks a tile to land on the detailed report page.
related: visual, tile, pin, workspace
word_family: report, dashboard, tile, page, pin
where_used: Management overviews | Detailed analysis | Daily monitoring
mini_conversation: A: Can I build a dashboard in Power BI Desktop? | B: No, dashboards are made in the Service by pinning visuals from reports.
misconception: ✗ Reports and dashboards are the same and can both be built in Desktop → ✓ Reports are built in Desktop or the Service, while dashboards exist only in the Service
contrast: Report vs dashboard: a report has many interactive pages from one model, a dashboard has one page of pinned tiles.
avoid: Do not cram every visual onto a dashboard, keep it to the key numbers.
memory_trick: Report is a book, dashboard is a poster.
real_project: Pinning five key sales visuals to a dashboard that executives open every morning.
real_interview: An interviewer may ask: What is the difference between a Power BI report and a dashboard?
real_daily: It is like a full book and a poster that sums up its main points.
mcq_question: Where can a dashboard be created?
mcq_options: A) In Power Query B) Only in the Power BI Service C) In Excel only D) Only in Power BI Desktop
mcq_answer: B
mcq_why: Dashboards are made in the Service by pinning tiles.
fill_blank: A dashboard is made by ____ visuals from reports onto one page → pinning
apply: A manager wants one screen with key numbers from two reports. What should you build? → A dashboard with tiles pinned from both reports
explain_task: Explain the difference between a report and a dashboard in three lines.
own_task: Choose five visuals you would pin to a dashboard for a shop owner.

@PBI-007
topic: 01 Basics
level: Beginner
term: Import vs DirectQuery
cue: Which two storage modes decide whether Power BI keeps a copy of your data or asks the source every time?
category: Storage mode
frequency: Very high
importance: 5
origin: Some data is small and fast to copy while other data is huge or must be live, so Power BI offers both a stored copy and a live query option.
pro_tip: Choose Import by default and use DirectQuery only when the data is too large or must be real time.
memory_story: Import is photocopying a book to read at home, and DirectQuery is going to the library every time you need a page.
visual: One arrow carries a full copy into Power BI, another arrow keeps asking the source each time.
emotion: The relief of fast visuals when the data is already inside the model.
definition: Import loads a compressed copy of the data into Power BI, while DirectQuery sends queries to the source each time a visual is used.
explanation: In Import mode the data is stored in the model's fast in-memory engine and refreshed on a schedule, so visuals are quick and all DAX features work. In DirectQuery mode nothing is stored, each visual sends a query to the source, so data is current but slower and some features are limited.
simple_explain: Import copies the data into Power BI, which is fast but needs refreshing. DirectQuery leaves the data where it is and asks every time, which is current but slower.
analogy: Import is photocopying the book, DirectQuery is visiting the library each time.
formula_rule: Import = copy + fast + scheduled refresh. DirectQuery = live + slower + source does the work.
example_1: A monthly Excel sales file is loaded in Import mode.
example_2: A huge live transactions database is queried with DirectQuery.
example_3: A report mixes both modes in one composite model.
related: refresh, composite model, aggregations, gateway
word_family: Import, DirectQuery, Live connection, storage mode, refresh
where_used: Choosing report performance | Large data | Real-time reporting
mini_conversation: A: Our database is huge and changes every second. | B: Use DirectQuery so each visual asks the source for current data.
misconception: ✗ DirectQuery is always better because the data is live → ✓ DirectQuery is usually slower and has feature limits, so Import is the better default
contrast: Import vs DirectQuery: Import stores a copy and needs refresh, DirectQuery stores nothing and queries the source each time.
avoid: Do not choose DirectQuery just to avoid scheduling a refresh.
memory_trick: Import imports a copy, DirectQuery directly asks.
real_project: Using Import for a monthly finance model and DirectQuery for a live operations table.
real_interview: An interviewer may ask: When would you choose DirectQuery over Import?
real_daily: It is like photocopying a book versus going to the library every time.
mcq_question: Which storage mode keeps no copy of the data inside the model?
mcq_options: A) Offline B) Dual copy C) DirectQuery D) Import
mcq_answer: C
mcq_why: DirectQuery sends queries to the source each time and stores no data.
fill_blank: With ____ mode the data is stored in the model and refreshed on a schedule → Import
apply: Which mode would you choose for a small file that changes once a month? → Import
explain_task: Explain the difference between Import and DirectQuery in three lines.
own_task: Write one real situation for Import and one for DirectQuery.
