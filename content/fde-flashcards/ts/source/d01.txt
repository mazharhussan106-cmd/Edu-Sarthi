topic: 01 JavaScript Core
level: Beginner
term: let, const and var
cue: Which three keywords declare variables, and which one should you reach for first?
kind: Declaration keyword
frequency: Very high
importance: 5
origin: Early JavaScript had only var, which caused surprising bugs, so let and const were added to give clearer rules about scope and change.
pro_tip: Default to const, and use let only when the value must change.
memory_story: Const is a name tag glued to one person, let is a tag you may move, and var is a tag that floats around the whole function.
visual: Three labelled boxes, one sealed, one changeable and one leaking outside its room.
emotion: The relief of bugs disappearing once variables stay in their blocks.
meaning: const declares a binding that cannot be reassigned, let declares a block-scoped binding that can be reassigned, and var declares a function-scoped binding that is hoisted.
code: const apiUrl = "https://api.example.com";¶let retries = 0;¶retries += 1;¶if (true) { var leaked = "visible"; let hidden = "blocked"; }¶console.log(leaked);
output: visible
explanation: A const binding cannot point to a new value, but an object stored in it can still be changed. let and const live only inside the braces where they are written. var ignores blocks, so a value declared inside an if statement is visible outside it. Variables from let and const exist in a temporal dead zone before their line, and reading them there throws an error.
simple_explain: Use const by default, let when you must reassign, and avoid var in new code.
analogy: Const is a name tag glued to one person, let is a tag you may move, and var is a tag that floats around the whole room.
syntax: const name = value; | let name = value;
anatomy: const = fixed binding | let = changeable binding | block = the braces that limit scope
example_1: const taxRate = 0.18;
example_2: let counter = 0; counter++;
example_3: for (let i = 0; i < 3; i++) { console.log(i); }
variation: const user = { name: "Asha" }; user.name = "Ravi";   // allowed, the object itself changes
used_with: loops, functions, modules
related: scope, closures, hoisting, objects
alternatives: Object.freeze to block changes inside an object
where_used: Every JavaScript file | Loops | Configuration
mini_conversation: A: Why did my variable still exist after the if block? | B: You used var, which ignores block scope, so switch to let or const.
misconception: ✗ const makes the value completely unchangeable → ✓ const only stops reassignment, and objects inside it can still change
confused_with: let vs var: let is block scoped, var is function scoped.
avoid: Do not use var in new code.
wrong_code: const total = 0;¶total = total + 5;
right_code: let total = 0;¶total = total + 5;
memory_trick: Const first, let when needed, never var.
real_project: Replacing var with const and let removed a loop bug in a customer script.
real_interview: An interviewer may ask: What is the difference between let, const and var?
real_daily: It is like a name tag that is either glued, movable or loose.
mcq_question: Which keyword should you use for a value that never changes?
mcq_options: A) let B) var C) function D) const
mcq_answer: D
mcq_why: const prevents reassignment and signals intent.
fill_blank: A variable declared inside braces with let is limited to that ____ → block

task_answer: const maxUsers = 100;

practice_answer: Yes, only reassigning the binding itself is blocked.

explanation: In object destructuring, names must match the keys, and a colon renames them. An equals sign gives a default. Array destructuring goes by position. The rest syntax collects what remains. Spread creates shallow copies, and later keys override earlier ones, which is handy for updates.
simple_explain: Destructure to take values out, and spread to copy and combine.
analogy: Destructuring is unpacking a suitcase onto shelves, and spread is tipping one suitcase into another.
syntax: const { a, b: c = 1 } = obj; const [x, ...rest] = arr; const copy = { ...obj };
anatomy: { } = by name | [ ] = by position | ... = rest or spread | = value = default
example_1: function show({ name, age }) { return name + age; }
example_2: [a, b] = [b, a];   // swap two existing let variables
example_3: const all = [...list1, ...list2];
variation: const { data: { id } } = response;   // nested destructuring
used_with: function parameters, props, immutable updates
related: objects, arrays, React props, function parameters
alternatives: Object.assign | concat
where_used: React props | API responses | State updates
mini_conversation: A: How do I update one field without changing the rest? | B: Spread the old object and override that field.
misconception: ✗ Spread makes a deep copy → ✓ It copies only the first level, so nested objects are still shared
